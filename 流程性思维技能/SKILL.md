# 流程性思考

## Overview

流程性思考是以时间顺序对思路进行系统性梳理，发现规律、找到解决问题办法的思维模式。核心动作是"捋这根时间线"——既能正向捋，也能反向捋。它是人的本能（动物闻声抬头、饿了进食），训练目标是把它从本能变成下意识的思维习惯。

与其他思维模式的分野：演绎推理从一般到特殊，归纳推理从部分到整体，二者都可能因前提不真、不全或部分不代表全部而结论错误；流程性思考的核心是**寻找前后环节的必然联系**，环环相扣，提高判断准确性。

## 何时使用

- 面对复杂问题，感觉千头万绪不知从哪入手
- 设计、优化或检查工作流程 / 项目流程 / 活动流程
- 给事项排先后：汇报顺序、谈判顺序、谈话顺序、裁员顺序
- 判断一件事的关键环节，决定资源投向
- 业务竞争力分析、改良式创新、行业趋势预判
- 绩效管理（PDCA）、复盘、辅导下属
- 诊断"为什么别人办事就是比我周全"

不适用：已有明确 SOP 的重复执行（照做即可，但可回头用本方法反思 SOP 本身）。

## 核心工作流（五步）

### 第 0 步：目标先行

先定目标，再定流程。流程是实现目标的途径；目标不同，流程差异巨大。

- 动笔前先写下"我要达成什么"，列出目的的可能变体并聚焦其一
- 高端饭店 vs 小吃店、婚礼的四种目标（广而告知 / 收钱 / 给长辈交代 / 给女方美好回忆）→ 流程设计完全不同
- 最大失误：把多个目的揉在一起出手（如空降任职时"先查账"实为自保，不是做业绩）

### 第 1 步：判定主流程（四种方法）

| 方法 | 判据 | 案例 |
|---|---|---|
| A 角色覆盖法 | 某角色的动作包含绝大多数其他角色的动作 | 婚礼 → 新娘 |
| B 服务对象法 | 服务的角色是谁，就以被服务者的流程为主 | 课程 → 学员 |
| C 物品/信息流转法 | 所有角色都为同一物品或信息服务 | 快递 → 货物流转；网店品类少时 |
| D 多主流程并存 | 两类角色流程差异大、交集小 | 滴滴 → 乘客端 + 司机端 |

多主流程并存复杂度高，但一旦做成，壁垒也高。

### 第 2 步：列环节、排顺序

流程中的每个步骤为一个环节。排序逻辑分两类：

- **硬逻辑**：别无选择（先有食物才能吃；扫码、疫苗等法律法规）——无需学习
- **软逻辑**：可设计、可优化——才是学习重点，分两种：
  - **明显逻辑**：一眼可辨（先洗脸再刷牙，个人偏好，无对错）
  - **隐含逻辑**：能力分野所在，详见下节

### 第 3 步：分清产品流程与项目流程

- **产品流程在前，项目流程在后；产品流程决定项目流程**
- 先想清楚"最终要的结果是什么、用户怎么用它"（手机先有使用流程再有开发流程；婚礼先有婚礼设计再定酒店——先交钱定酒店，产品设计就被资源锁死）
- 考虑角色时不只看单一动作，要看**前后的动作**：领导从到到走的全程服务是产品的一部分，把人当工具人等于用人朝前不用人朝后

### 第 4 步：定位关键环节并投入资源

环节太多不能平均用力。用三列表定位：

| 环节 | 承担职位 | 该职位产出的可控性 |
|---|---|---|
| 如：点餐 | 服务员 | √ 完全可控 / ◐ 可影响 / × 完全不可控 |

- 前提：任职者能力态度达标；不把人的因素提前放进来
- 出现完全不可控环节 = 业务结果不可控（不正常）；大量可影响环节 = 事难做但壁垒高
- **关键环节随目标、战略、人际、时期变化，每次重新梳理，绝不抄作业**（海底捞的关键环节是用餐服务，景区饭店是拉客；房地产黄金年代是拿地，"活下去"之年是销售和银行回款）
- 投入规则：资源优先投关键环节；多个关键环节同为短板，从流程靠前的入手
- 关键环节任职者决定博弈地位：技能稀缺难替代者溢价能力强（预制菜裁掉切配只留颠勺，就是在重造流程、打掉大厨环节）

## 隐含逻辑：能力分野所在

隐含逻辑有两种：

1. **应该存在但未能被发现的环节**——一切顺利时想不到它存在（签到台没写课程名、没有对接联系人）
2. **不同场景下环节有更好排序但未意识到**（定工作计划：先找领导沟通还是先写方案，取决于上级是控制欲强还是甩手掌柜）

判别训练：问自己"这个顺序是放之四海而如此，还是只适用此情此景？"大多数人下意识认为一种顺序适用于所有场景，这正是问题。

**把隐含逻辑变成明显逻辑的五种方法**：

1. 比较法——两种做法摆在一起比效果（带团队时最直接有效）
2. 向专家学习——观察法（看高手先做什么再做什么）+ 请教法（问三件事：有哪些环节、哪个在前、为什么在前）
3. 总结法——归纳行业逻辑差异（互联网试错上线 vs 制造业一次做对，源于成本与变化速度差异）
4. 复盘——按流程、分角色回放，专找"什么顺序效果更好"
5. 数据分析——从数据中挖掘用户真实使用逻辑（App 菜单按使用频率自动上移）

管理者天职：让自己的明显逻辑变成下级的明显逻辑。用自己的标准替代别人的标准（"这还用教？"）是最常见错误。考察下属时，听计划着重听**做事的顺序**。

## 三种思维模式的配合（六字要诀：流程、分类、验证）

- **流程**：领域陌生、无从下手时先用——先流程再分类。越不熟悉越要用流程梳理
- **分类**：领域熟悉时直接用。MECE 原则（穷尽所有、没有交叉）；层次尽可能少；注意并形分类易遗漏（运输分了铁路公路航空海运，漏了蓄力运输），串形分类基于流程不易遗漏
- **验证**：正向 = 分角色把流程各走一遍，发现缺失（婚礼上酒逆子发小安排到哪桌）；反向 = 特例性验证，按流程倒退，每个环节问"出问题前端有无应对"（直播备网、备摄像机）。风险三问：概率大不大、影响大不大、应对代价高不高——想到了而不准备，是权衡后的决策；没想到，是碰巧

## 应用速查表

| 场景 | 入手方式 |
|---|---|
| 解决问题 | 先画流程；**分析问题倒着来**（从后往前找转化率下滑的环节），**解决问题顺着来**（前面的坑不填，后面白干） |
| 工作控制 / 绩效 | 从关键环节上的人入手；PDCA 必须从计划入手（直接上制度打分必然糟糕）；绩效反馈**员工先说、上级后说** |
| 竞争力分析 | 横轴环节、纵轴竞争力画曲线；提升从关键环节的短板入手 |
| 改良式创新 | 逐环节对标紧盯的对手，从自己和他人的动作不适点出发；不拍脑袋、不迷信头脑风暴 |
| 趋势预判 | 画行业全流程链条，看自己所在环节及上游的前途；为可危环节提供服务的公司自身可危 |
| 排序决策 | 分清硬逻辑/软逻辑、明显/隐含逻辑，识别场景差异 |
| 减少失误 | 分角色正向验证 + 特例反向验证 + 风险三问 |

## 铁律

1. 目标不清，不动流程
2. 推理手段的正确性不代表结论的正确性；流程性思考的可信度来自环节间的必然联系
3. 分析倒着来，解决顺着来
4. 相似流程、目标不同，关键环节就可能不同；每次重新梳理
5. 产品流程在前，项目流程在后
6. 学逻辑，不恋工具——工具背后是逻辑，逻辑懂了工具可自创
7. "没做"必须是盘算后的决策，不是没想到
8. 快速判断一门课/一本书：目录里看不出流程或分类，可用性存疑
