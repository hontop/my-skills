# 教材蒸馏方法

## 目标

把一本教材变成一组**可训练、可判定、可排程**的知识单元（KU）。蒸馏不是写摘要——摘要是压缩信息，蒸馏是切出能练的块。

## 三类教材的切分路径

| 类型 | 取结构的方式 | 切分粒度 |
|---|---|---|
| 书 | 目录 → 章 → 节 → 小节；每章首段与末段定范围 | 章 → 节 → KU |
| 视频 | 课节标题 + 时长 + 简介/字幕；按内容拐点而非时间戳切 | 章节 → 节 → KU（单节超长则按拐点再切） |
| 文档 | 标题层级 + 示例/代码块位置 | 二级标题 → KU |

教材结构缺失时（用户只给书名）：用公开目录信息重建，并显式标注"目录为推断版本，第 2 周按实际内容校准"。

## 切分硬规则

- 单个 KU 首次学习 **≤60 分钟**；超出则再切。
- 单个 KU **≥10 分钟**；不足则与相邻同主题合并。
- 一个 KU 只承载**一个**可判定产出。承载两个产出 = 该切成两个 KU。
- 全教材 KU 数量建议：短教程 15–30 个，标准图书 40–80 个。超过 100 个说明切太碎，回到章节层重新合并。

## KU 字段规范

| 字段 | 取值 | 说明 |
|---|---|---|
| `id` | KU-001… | 按依赖拓扑后的顺序编号 |
| `title` | 一句短语 | 用"能做什麼"表述，不用名词堆砌 |
| `source` | 第3章 p.84-97 / 视频 P24-P31 | 必须可回溯到教材原处 |
| `type` | concept / procedure / case / drill | 概念 / 流程 / 案例 / 专项训练 |
| `bloom` | 理解 / 应用 / 迁移 | 决定出题层次 |
| `minutes` | 10–60 | 首次学习耗时 |
| `difficulty` | 1.0 / 1.3 / 1.6 | 影响排程耗时 |
| `prereqs` | [KU-008, KU-010] | 前置依赖 |
| `evidence` | 可判定的产出描述 | 见下 |
| `mastery` | 0–5 | 初始 0 |
| `interval_idx` | 0 | 复习间隔游标 |
| `review_due` | 日期或 null | |
| `attempts` | [] | [(date, score)] |
| `status` | pending / learning / done / exposure | |

## evidence 写法（最关键）

evidence 必须**可判定**：第三方看一眼就知道做没做到，不需要主观评价。

| 反面 | 正面 |
|---|---|
| 理解递归 | 手写快排并通过 5 组测试 |
| 掌握需求分析方法 | 对给定场景写出 3 条验收标准 |
| 学会这个函数 | 不看文档用它改写给定的 20 行代码 |
| 了解章节内容 | 闭卷列出该节的 4 个要点 |

写不出 evidence 的内容 → 标记 `type: exposure`，只排通读时间，不进训练队列、不做测验、不计掌握度。

## 依赖处理

1. 逐 KU 标 prereqs，构成有向图。
2. 拓扑排序 → 分层，同层内可任意顺序。
3. 出现环 → 打破规则：**先整体跑通，再回补细节**。把环中"最基础"的那个 KU 降为粗粒度先学，其余后置。
4. 依赖最多两层深度：A→B→C→D 这种链会让任何一环卡住就全线停摆，应压缩为 A→C 直连 + 并列。

## 通用领域的默认 evidence 形式

学科未指定时，按 KU 类型套用：

| type | 默认 evidence |
|---|---|
| concept | 闭卷复述要点 + 举出一个教材外的新例子 |
| procedure | 不看提示独立走完流程一遍 |
| case | 对新案例写出分析结论，且与要点对齐 |
| drill | 在限定时间内完成 N 次正确操作 |

## 输出

生成 `knowledge-map.md`（按层分组的 KU 表格 + 依赖图）与 `state.json`。
校验交由 `scripts/distill.py` 执行，它会报出：evidence 缺失、id 重复、依赖不存在、环、minutes 越界。
